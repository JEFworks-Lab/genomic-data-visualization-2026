### 4. If I perform non-linear dimensionality reduction on PCs, what happens when I vary how many PCs I use? Write a brief description of your figure so we know what you are visualizing.
First, when low numbers of principal components (PCs) are used (e.g., 1 to 3), the embedding of non-linear dimensionality reduction (tSNE) appears unstructured since the majority of the variance in the gene expression data, which may represent biologically meaningful variation, is not being captured. Second, when an increasing number of PCs are used (e.g., 5 to 10), the tSNE embedding becomes more distinctly structured and stable since the majority of the variance in the gene expression data, which may encapsulate biologically meaningful variation, is being captured. Third, when high numbers of PCs are used (e.g., 30 to 50), the tSNE embeddings change proportionally less in structure since very small variance in the gene expression data, and hence new information, is being captured. Overall, this suggests that utilizing a moderate number of PCs in tSNE typically offers the most informative embeddings, by capturing much of the variance while minimizing noise.

The three key points above are shown simultaneously by the animations on the left and the right, which compare a principal component analysis (PCA) scree plot and the resulting tSNE embedding, respectively, as the number of input PCs is varied across 1, 3, 5, 8, 10, 30, and 50. In the scree plot, the standard deviation (StDev), which is the square root of the variance, captured by each PC, is displayed; the highlighted, colored points represent the number of PCs used for the tSNE computation. In the tSNE embedding plot, the embeddings for each cell's spatial transcriptomics is displayed as a point following non-linear dimensionality reduction, and each point is colored based on the number of input PCs used.

### Code
```r
# Load the necessary libraries
library(ggplot2)
library(Rtsne)
library(gganimate)
library(magick)
library(viridis)

# Read in data
data <- read.csv('~/Documents/genomic-data-visualization-2026/data/Xenium-IRI-ShamR_matrix.csv.gz')
pos <- data[, c("x", "y")]
rownames(pos) <- data[, 1]
gexp <- data[, 4:ncol(data)]
rownames(gexp) <- data[, 1]

# Normalize
totgexp <- rowSums(gexp)
mat <- log10(gexp / totgexp * 1e6 + 1)

# Run PCA
pcs <- prcomp(mat, center = TRUE, scale = FALSE)

# Define PC counts to animate tSNE over
pc_steps <- c(1, 3, 5, 8, 10, 30, 50)

# Build a long-format scree dataframe for animation that marks which PCs are included at each step for highlighting
# Prompt to AI: "I ran pcs <- prcomp(mat) and I want to animate a scree plot over pc_steps <- c(1,3,5,8,10,30,50).
# Can you make a function that creates a long dataframe with PCs 1 to 50 repeated for each step with appropriate columns and one indicating whether each PC is in the first npcs?"
df_sdev <- do.call(rbind, lapply(pc_steps, function(npcs) {
  data.frame(
    PC = 1:50,
    sdev = pcs$sdev[1:50],
    npcs = npcs,
    included = (1:50) <= npcs
  )
}))

# Run tSNE separately for each requested PC count and stack embeddings into one long-format dataframe for animation
# Prompt to AI: "For each value in pc_steps, can you make a function that creates a long dataframe with appropriate columns based on running tSNE on the first npcs columns of pcs$x?"
set.seed(3226)
df_emb <- do.call(rbind, lapply(pc_steps, function(npcs) {
  message("Running tSNE on first ", npcs, " PCs ...")
  ts <- Rtsne::Rtsne(
    pcs$x[, 1:npcs, drop = FALSE],
    dims = 2,
    perplexity = 30,
    pca = FALSE,
    verbose = TRUE,
    check_duplicates = FALSE
  )
  emb <- ts$Y
  colnames(emb) <- c("tSNE1", "tSNE2")
  out <- data.frame(emb)
  out$spot <- rownames(pcs$x)
  out$npcs <- npcs
  out
}))

# Fix factor levels so the same PC count always maps to the same color across both plots
# Prompt to AI: "How do I adjust both dataframes so that the same npcs always get the same color in two different gganimate plots?"
df_sdev$npcs_f <- factor(df_sdev$npcs, levels = pc_steps)
df_emb$npcs_f  <- factor(df_emb$npcs,  levels = pc_steps)

# Define a shared theme so both panels look consistent when combined into one GIF
base_theme <- theme_bw(base_size = 12) +
  theme(legend.position = "bottom")

# Left: Scree plot with requested PC count colored
# Prompt to AI: "How do I make a ggplot that animates through each npcs value on a PCA scree plot with PC Index on the x-axis and StDev on the y-axis?
# An animated colored/turbo line passing through a solid grey background line for each change in npcs should also be implemented."
p_sdev <- ggplot(df_sdev, aes(x = PC, y = sdev, group = 1)) +
  geom_line(color = "grey70", linewidth = 0.6) +
  geom_point(color = "grey70", size = 1.2) +
  geom_line(
    data = df_sdev,
    aes(color = npcs_f, y = ifelse(included, sdev, NA_real_)),
    linewidth = 1,
    na.rm = TRUE
  ) +
  geom_point(
    data = df_sdev,
    aes(color = npcs_f, alpha = included),
    size = 1.5
  ) +
  scale_alpha_manual(values = c(`FALSE` = 0, `TRUE` = 1), guide = "none") +
  scale_color_viridis_d(option = "turbo", end = 0.98, name = "Number of PC(s)") +
  guides(color = guide_legend(nrow = 1)) +
  labs(
    title = "PCA Scree Plot Highlighting {closest_state} PC(s)",
    x = "PC Index", y = "StDev"
  ) +
  base_theme
anim_sdev <- p_sdev +
  transition_states(npcs, state_length = 7, transition_length = 0.3) +
  ease_aes("linear")

# Right: Animated tSNE scatter plot with requested PC count shown
# Prompt to AI: "How do I make a ggplot that animates through each npcs value on a tSNE plot with tSNE1 on the x-axis and tSNE2 on the y-axis?
# Each change in npcs should also be animated based on an altering color/turbo scheme."
p_tsne <- ggplot(df_emb, aes(x = tSNE1, y = tSNE2)) +
  geom_point(aes(color = npcs_f), size = 0.5, alpha = 0.85) +
  scale_color_viridis_d(option = "turbo", end = 0.98, name = "Number of PC(s)") +
  guides(color = guide_legend(nrow = 1)) +
  labs(
    title = "tSNE on {closest_state} PC(s)",
    x = "tSNE1", y = "tSNE2"
  ) +
  base_theme
anim_tsne <- p_tsne +
  transition_states(npcs, state_length = 7, transition_length = 1.25) +
  enter_fade() + exit_fade() +
  ease_aes("cubic-in-out")

# Render both animations to image sequences (magick) so that frames can be stiched side-by-side
gif_sdev <- animate(anim_sdev, fps = 10, nframes = 120, renderer = magick_renderer())
gif_tsne <- animate(anim_tsne, fps = 10, nframes = 120, renderer = magick_renderer())

# Combine and plot corresponding frames from both animations side-by-side
# Prompt to AI: "How do I combine two magick figs into one gif with gif_sdev on the left and gif_tsne on the right, frame-by-frame?"
combined <- image_append(c(gif_sdev[1], gif_tsne[1]))
for (i in 2:length(gif_tsne)) {
  combined <- c(combined, image_append(c(gif_sdev[i], gif_tsne[i])))
}
combined

# Write the final combined animation to disk as a GIF
out_file <- "hwEC1_yhodo1.gif"
image_write(combined, path = out_file)
```
